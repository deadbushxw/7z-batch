# zbatch · 7z 批量压缩 / 解压工具

一个 Windows 上的图形化批处理外壳，把「一堆文件按天归档成加密压缩包 + 当天清单」这件事变成几次点击。

- 单文件 Python + tkinter，**零第三方依赖**（只用标准库），不联网
- 压缩/解压全部交给 `7z.exe`，本工具只负责批量编排、命名、核对与还原
- 默认工作目录就是工具自己所在的文件夹，拷到哪就能在哪用

---

## 项目动机

手工做「一天一批、一个文件一个包、另存一份清单」这种归档，重复劳动多且容易出错：编号容易重、改名容易漏、清单容易和实际对不上。这个工具把整套规则固定下来，并且**每次打包后都实际核对包内内容**，避免出现「以为备份好了、其实包里是空的」。

原名 `7z批量工具` 的计划在落地时改成了 ASCII 文件名（`zbatch.py`），因为批处理文件里出现中文时会依赖系统 OEM 代码页，换台机器就可能乱码失效。界面文字仍然是全中文。

## 环境要求

| 依赖 | 说明 |
|---|---|
| Windows | 用了 `msvcrt` 式的路径探测、`mbcs` 回退解码与 DPI 感知 API，不跨平台 |
| 7-Zip | 需能找到 `7z.exe`：优先查 `PATH`，其次查 `C:\Program Files\7-Zip\` 与 `Program Files (x86)`。找不到时界面顶部会标红提示并禁止执行任务 |
| Python 3 | 需带 `tkinter`。Python 官方安装包默认包含；实测环境为 3.11.9 |

没有 `pip install` 这一步，也不需要装 `py7zr` 之类的库。

## 快速开始

1. 把 `zbatch.cmd`、`zbatch/`、`README.md` 一起放进你要归档的文件夹
2. 双击 `zbatch.cmd`
3. 在顶部**密码框输入密码**——留空无法开始，因为本工具始终加密
4. 压缩页点「扫描预览」，核对将要生成的包名，可用最左侧「压缩」列勾掉个别文件
5. 点「开始压缩」

一次压缩会为每个文件生成一个包，改掉源文件名，最后补一份当天的清单包。

**默认工作目录的判定规则**：脚本自己待在 `zbatch/` 子文件夹里，而入口 `zbatch.cmd` 在上一级，所以默认工作目录取**上一级**，也就是放 `zbatch.cmd` 的那个文件夹。如果你把 `zbatch.py` 单独拷出去用（不带子目录），默认工作目录就变成脚本自己所在目录。想固定去别处，用界面上的「选择目录…」，之后会被记住。

## 命名规则（核心契约）

| 对象 | 命名 | 例子 |
|---|---|---|
| 文件包 | `{YYYYMMDD}{NN}.7z` | `2026092501.7z` |
| 目录包（当天清单） | `{YYYYMMDD}index.7z` | `20260925index.7z` |
| 清单本体（在目录包内） | `{YYYYMMDD}index.txt` | `20260925index.txt` |
| 压缩后的源文件 | `_{原文件名}.{原扩展名}` | `_报告.docx` |
| 解压出的文件 | `_{原文件名}.{原扩展名}` | `_报告.docx` |

- `{YYYYMMDD}` 取自**文件自身的修改时间**，跨天的文件会分到不同日期的包
- `{NN}` 是**当天内**的序号，2 位零填充，按修改时间从老到新：最老的 `01`；某天超过 99 个自动升 3 位
- 识别规则：文件包 `^(\d{8})(\d{2,3})\.7z$`，目录包 `^(\d{8})index\.7z$`（大小写不敏感）

### 同一天多次运行

序号基线来自**磁盘上当天已有包的最大序号**，不是内存里的计数器。所以：

| 场景 | 结果 |
|---|---|
| 首次运行，压 3 个文件 | `2026092501.7z`、`02`、`03`，目录包内容列 01~03 |
| 当天又放进 2 个文件，再跑一次 | 新包接着排 `04`、`05`；**已有包绝不覆盖、不重排**；目录包原地更新为 01~05 |
| 当天第三次运行，文件夹里只剩 `_` 文件和 `.7z` | 提示「没有需要压缩的文件」，**不动**目录包 |
| 取消了「包含 `_` 开头的文件」再跑 | `_原名` 重新打包为 `06`…，且不会再被二次改名 |

目录包是**当天全量累计**的：每次运行结束时按磁盘上的实际包重建，所以一天跑几次，清单里就有几条。重建采用「先写临时文件再原子替换」，中途崩溃不会毁掉当天唯一那份清单。

清单末行还有一条 `#ZBATCH1 ` 开头的机器可读数据（JSON），给工具自己回读用。因为 `{YYYYMMDD}index.7z` 同时也是「当天每个包里装的是什么」的索引，解压页就能靠它一次拿到当天所有包的文件名，不必逐个开包（详见「批量解压」一节）。上面那张人看的表格保持不变；旧清单没有这一行时，工具会退回按表格解析，照样能用。

## 四种操作

### 批量压缩

只处理**工作目录第一层**的普通文件（不递归子目录），自动跳过：

- 所有 `.7z`（含目录包）
- `_` 开头的文件（上次压缩留下的，可用勾选框改为包含）
- **点开头的文件**（`.gitignore`、`.gitattributes`、`.editorconfig`、`.env` 这类仓库/工具配置）
- 工具自身的文件（`zbatch.cmd`、`README.md`、`LICENSE`、`zbatch/` 文件夹），**永远不碰**

因为默认工作目录就是放 `zbatch.cmd` 的那个文件夹，也就是说这个工具的目录**通常就是仓库根目录**——.gitignore 之类的文件按前缀一刀切跳过，比一个个往排除名单里加更不容易漏。如果确实要归档某个点开头的文件，勾上「包含点开头的文件」即可；工具自身的文件不受该勾选框影响。

执行顺序是：逐文件打包 → **核对包内内容** → 改名源文件 → 生成当天目录包。任何一步失败都不动源文件。

### 生成目录包

给「文件夹里只剩格式化好的压缩包」准备的：不需要任何待压缩文件，直接扫描工作目录里所有 `{YYYYMMDD}{NN}.7z`，按天重建 `{YYYYMMDD}index.7z`。

适用场景：

- 压缩完、清理掉源文件之后想补一份清单
- 从别处拷来一批包，想配上统一的清单
- 清单和实际对不上，想按磁盘现状刷新

一次会为**所有**出现的日期各生成一份，已有的目录包原地覆盖（不会越攒越多）。清单里的每一条都是当场读包得到的，不是从旧清单抄的。

### 批量解压

三种模式，共用同一套解压与改写逻辑：

| 模式 | 用法 |
|---|---|
| 按天批量 | 选日期 → 解压该天全部（含目录包） |
| 按天按序号 | 选日期 → 在列表里点选 → 解压选中 |
| 自由选择 | 左右两栏：左边按天筛选后点选，右边实时列出已选中的 → 解压选中 |

**选中方式（模式二、模式三通用，不需要按 Ctrl）：**

| 操作 | 效果 |
|---|---|
| 点一下 | 选中该项；再点一下取消选中 |
| Shift + 点 | 把「上一次点到这一次点」之间（含两端）的项一并选中，不丢掉原有选中 |
| 点右栏的项 | 从已选中移出；Shift + 点移出整个区间 |

模式三左边一栏只列压缩包、可按天筛选；**筛选只是视图**，切换筛选条件不会丢掉已经选中的包——它们仍留在右栏。名字不符合 `{YYYYMMDD}{NN}.7z` 的包（比如 `backup.7z`）也能被选中，只是只在「全部」筛选下出现，不会被藏起来。右栏按日期 + 序号排列。

模式二切换日期会清空选中（换了一批包），因为它的作用范围就是那一天。

### 看到包里装的是什么

包内文件名是加密的，所以**输入密码后**列表会自动读出每个包的原始文件名，「包内原文件」一列就填上了。也可以随时点「读取包内文件名」手动刷新。

读取是分层的，这是为了不让包多的文件夹卡住：

| 情况 | 做法 | 代价 |
|---|---|---|
| 当天有 `{YYYYMMDD}index.7z`，且清单里的打包时间和包的修改时间一致 | 直接读清单 | 每天 1 次 7z 调用 |
| 当天没有目录包、清单里没有这个包、或包在清单生成后被改动过 | 逐个读该包 | 每包 1 次 7z 调用 |

实测 208 个包 / 8 天的规模：逐个读要 **17.2 秒**，清单优先只要 **0.94 秒**（快 18 倍）。结果按「路径 + 大小 + 修改时间」缓存，包一变缓存自动失效。

注意那条「打包时间」的判断：清单是打包那一刻的快照。如果某个包在清单生成之后被换掉，清单里的名字就不可信了——这时它会退回逐个读，报出包内**实际**的文件名，而不是照抄清单。读不出来的包（密码不对、包损坏）会明确标成 `⚠ 读不出（密码不对或包已损坏）`。

解压本身的行为：

- 先解到临时目录，再把每个文件**只对文件名**加 `_` 前缀，移动到输出目录
- 包内的相对层级会保留，`_` 只加在最内层的文件名上
- 目标重名时自动追加 `-2`、`-3`，**绝不覆盖**
- 解出的清单 txt 也带 `_` 前缀，日志里会标注「目录文件，不是原始文件」
- 输出目录默认为工作目录，建议**另选一个空目录**——否则解出的文件会和工作目录里压缩时留下的 `_原名` 撞名，变成 `_原名-2`

### 一键删除

删除工作目录下所有 `_` 开头的文件和文件夹。

- 删除前弹窗列出**项数、总大小和前 15 个名字**，确认后才动手
- 硬排除：所有 `.7z`、工具自身文件
- 注意范围就是「`_` 开头」，所以 `__pycache__`、`_old` 这类目录也会被算进去。这符合「`_` = 可丢的内部产物」的约定，弹窗里也会逐个列出来给你核对

## 压缩参数

对齐 7-Zip 图形界面里的设置：

| 界面项 | 实际参数 | 说明 |
|---|---|---|
| 压缩格式 | `-t7z` | 7z 格式 |
| 压缩等级 `0 - 仅存储` | `-mx=0` | 不压缩、只打包，速度快 |
| 加密文件名 | `-mhe=on` | 表头加密，没密码连包内文件名都看不到 |
| 密码（AES-256） | `-p<密码>` | 7z 的数据加密固定为 AES-256 |
| 路径模式 `相对路径` | 以工作目录为 `cwd`、只传文件名 | 包内是干净的文件名，不带盘符和上级目录 |
| —— | `-spd` | 关闭通配符展开，文件名里的 `*` `?` 原样处理 |
| —— | `-sccUTF-8` | 让 7z 用 UTF-8 输出，中文名不乱码 |

打包后的包实测为 `Method = Copy 7zAES`，即「仅存储 + AES-256」，表头加密（无密码时 7z 会直接索要密码）。

### 两个必须知道的密码约束

- **密码不能为空。** 密码为空时 7z 根本不加密（产出的包 `Encrypted = -`，退出码 255）。界面会拦下来。
- **密码不能含英文双引号 `"`。** 这是 7-Zip 命令行解析的限制，含该字符时 7z 直接报命令行错误（退出码 7）。界面会拦下来并说明原因。

空格、`&`、`$`、反引号、单引号、中文都可以正常使用。密码只存在内存里，不写配置文件。

## 设计与行为细节

**打包后一定会核对包内内容。** 这不是可选优化。7-Zip 遇到含 `*` 或 `?` 的文件名时会**静默产出一个空包并报告成功**（打印 `Files read from disk: 0`、退出码 0、`Everything is Ok`）。所以每个包打完都会重新列一遍包内条目，核对文件名、大小和加密标记；不通过就删掉坏包、源文件保持原名不动的状态。

**0 字节文件是特例。** 空文件没有数据流，7z 无可加密，条目会显示 `Encrypted = -`，但表头依然是加密的。核对逻辑因此只在有数据流时才要求条目级加密标记。

**「打包后完整校验」是可选项。** 勾上会额外用 `7z t` 把整个包读一遍校验 CRC。对大文件而言耗时翻倍，所以默认关闭。即便关闭，上面说的文件名/大小/加密核对也始终执行。

**取消是响应式的。** 点「取消当前任务」会直接杀掉正在运行的 7z 进程，并在文件边界停下；已完成的包不回滚。

**失败不阻断整批。** 单个文件失败只让它自己失败，其余文件继续；日志里该条标红，最后给出 `成功 x / 失败 y` 汇总。界面全程跑在工作线程里，不会卡死。

**取消勾选会保留已有编号。** 目标包名已存在时从当天最大序号往后顺延，而不是去填中间的空号——避免和已经写进清单的编号对不上。

## 已知限制

- **不递归子目录**，只处理工作目录第一层
- **不做「压缩后直接删源文件」**：按设计是改名成 `_原名`，删不删由你点「一键删除」决定
- **不支持拖拽文件进窗口**：tkinter 原生不支持，要引 `tkinterdnd2`，会破坏零依赖
- **没有撤销/回滚**，也**没有包内预览**与定时自动归档
- 生成目录包时每个包都要调一次 `7z l`（只读表头，很快）；包特别多时会有可感知的耗时，进度条会显示进度
- 清单里若某个包读不出来（密码不对或包损坏），会警告并跳过该包，清单如实只列能读到的

## 常见问题

**顶部提示找不到 7z**
装 7-Zip，或把 `7z.exe` 所在目录加进 `PATH`，然后重启工具。

**提示「密码含有不支持的字符」**
把密码里的英文双引号 `"` 换掉，原因见上文。

**解压后多出一堆 `_xxx-2` 文件**
解压输出目录和工作目录相同，和工作目录里压缩时留下的 `_原名` 撞名了。换一个空的输出目录。

**清单里的序号和我预期的不一样**
序号是按**文件修改时间**、以**天**为单位、从**磁盘已有包的最大序号**往后排的。想确认当前状态，直接看「生成目录包」重建出来的清单。

**一键删除会不会误删压缩包**
不会。所有 `.7z` 被硬排除，删除前还会列出完整清单让你确认。

## 关于隐私与 .gitignore

仓库里的 `.gitignore` 排除了三类东西，都是本机状态或私人数据，不适合推到 GitHub：

| 排除项 | 原因 |
|---|---|
| `zbatch/zbatch.config.json` | 记的是这台机器上的工作目录、窗口尺寸等本机状态 |
| `*.7z` / `*.7z.tmp` | **工具产出的归档是私人数据**。这个仓库通常就放在归档文件夹里，不排除的话会被一起推上去 |
| `.zcode/`、`__pycache__/`、编辑器杂物 | 工具与系统生成的中间文件 |

如果你希望仓库里带一两个样例包用于演示，把 `.gitignore` 里那一行改成白名单即可。另外注意：**`gitignore` 只影响未跟踪的文件**——如果某个 `.7z` 已经被提交过，需要 `git rm --cached` 才能真正移除。

代码与文档里不含用户名、本机绝对路径、凭据或邮箱；唯一的绝对路径是 `C:\Program Files\7-Zip\`，那是 7-Zip 的标准安装位置。密码只存在于内存中，既不落盘也不会写进日志。

## English

`zbatch` is a lightweight Windows GUI wrapper around `7z.exe` for day-bucketed archiving: it packs each file into its own encrypted archive named `YYYYMMDDNN.7z`, writes a per-day manifest archive `YYYYMMDDindex.7z` listing the original filenames, renames the sources with a `_` prefix for one-click cleanup, and can restore everything through three batch-extract modes. The extract view can show the original filenames inside each archive — read from the per-day manifest when possible, falling back to opening individual archives when a manifest is missing or stale.

Built as a single Python file with tkinter and **no third-party dependencies**. It always encrypts (AES-256, encrypted filenames) and refuses empty passwords. Every archive is verified right after packing — 7-Zip silently produces empty archives for filenames containing `*` or `?` while reporting success, so verification is mandatory rather than optional. Run `python zbatch\zbatch_selftest.py` for the 116-assertion end-to-end suite.
